## A. Executive Summary

**What the project is:** a neuro-symbolic safety shield over SparseDrive, an end-to-end neural planner. Candidate trajectories `(6,2)` at 0.5 s grid are translated to integer Answer Set Programming facts (cm ×100, squared speeds, T=0..5 @ 1.0 s), checked against a 63-rule Clingo traffic-law catalog (15 families R1–R15), and repaired by one of two corrector engines — a map-aware heuristic fixpoint (production default) or an ASP-constrained projected-gradient QP (`CorrectorQP`) whose bounds are emitted by the solver itself and re-validated symbolically.

**Present implementation status:**
- Checker → corrector → pipeline path is fully wired and exercised: `TrajectoryChecker.check()` (`asp-safety/src/checker.py`), `TrajectoryCorrector.correct()` / `CorrectorQP.correct()` (`asp-safety/src/corrector.py`), `ConstraintOptimizer.solve()` (`asp-safety/src/constraint_optimizer.py`), `SafetyLayerPipeline.run()/run_batch()` (`asp-safety/src/pipeline.py`), `SparseDrivePlanner.predict()/predict_frame()` (`asp-safety/src/neural_planner.py`), `NuScenesLoader` (`asp-safety/src/data_loader.py`).
- 63-rule catalog exists with all 15 files emitting constraint atoms; `check(include_constraints=True)` 3-tuple contract exists; `corrector_mode='heuristic'|'qp'` exists on pipeline and `--corrector` on calibration.
- Test suite claims 120 green at S17/S18 closeout, 122 green after P-23 increment 1 (2 added regression tests). Registry tripwire (`test_rule_registry`) enforces 73/73 catalog findings fire. This audit did **not** re-run pytest, so green status is inherited from `session.md` S23/S24 + `docs/test_coverage.md`, not independently verified.
- Open-loop evidence is 10-scene nuScenes-mini only: warm temporal inference L2 11.54 m → 10.18 m; warm shield fix-rate 0.50 for **both** engines with identical scene sets (parity, not QP superiority); frozen-dump ablation QP 0.375 = heuristic 0.375 (caps 0.00, boxes 0.125→0.00 across P-23 increments); pure-QP without fallback 1/8 → 2/8 only at 10 rounds.
- Closed-loop evidence is a 15-run single-seed CARLA pilot (5 scenarios × off/heuristic/qp, Town10HD_Opt, lane plan engine because neural plan is OOD on CARLA): 13.3% collision (2/15, both unshielded S3 cut-in + S5 turn-conflict) vs 0 collisions on all 10 shielded arms. Statistically thin (n=2 events), confounded by `wall_cap` holds, kinematic actors (S4 walker generates no physical collision), oracle-context shield, and 2 s replan-gap non-causality. Caveats are honestly ledgered in `docs/carla_harness.md` but the headline rate should not be quoted without them.

**Central contribution being attempted:** replacing a hand-tuned heuristic repair table with solver-emitted continuous bounds + joint-horizon optimization + symbolic re-validation — i.e. ASP as both veto **and** constraint generator. The honest measured result so far is **parity + a pure-lane latency win**, not superiority: the identified ceiling after three P-23 increments is **emission coverage, not projection convergence** (accumulated bounds hit `projection_cycle`; per-timestep boxes cannot express the coupled corridor a moving threat needs).

**Strongest findings supported by evidence:** (1) unusually thorough symbolic firing/quiet coverage with anti-vacuity guards; (2) warm temporal harness genuinely improves prediction (10/10 scenes); (3) threshold sweep honestly kept only `min_score 0.3→0.5`; (4) extrapolation honestly dropped; (5) QP/heuristic parity reproduced across four protocols (frozen dump, optimizer sweep, warm pipeline, warm tracked-replay).

**Most important unresolved problems:** (1) corrector latency 2.5–8.7 s vs 50–100 ms control budget — no real-time claim is supportable; (2) horizon-joint solving still open after 3 increments (scene-8 class; regression at 3r in inc3); (3) all nuScenes evidence is 10-scene mini; (4) closed-loop pilot is seed-1, lane-engine, kinematic; (5) `road_type`/`speed_limit` honestly omitted from map extraction so several rules are permanently silent on real data; (6) `nav_cmd` head semantics unverified; (7) B3 oracle / A4 / A6 / A7 ablations not run; multi-seed matrix (seeds 2–3, 45-row) not run; P-13 nav/ego wiring remainder open.

## B. Research Problem and Intended Contributions

**Research question (as documented):** end-to-end planners approximate roads/agents with learned priors; approximation is acceptable for navigation but not for safety claims (speeding, tailgating, red-light running are wrong in ways L2 improvement does not forgive). Can a declarative ASP layer supervise and repair neural plans with named rule guarantees, integer-arithmetic grounding performance, and measured behavioral safety (`paper/report.tex`, `docs/repository_deep_dive.md`, `asp-safety/README.md`)?

**Objectives (from `repo-knowledge.md` subdivisions, `asp-safety/README.md`, `docs/evaluation_design_asp_correction.md`):**
1. Integrate SparseDrive inference (real weights + deterministic placeholder fallback).
2. Formalize ~63 traffic rules across 15 families with integer-cm, squared-distance, no-`sqrt` discipline (`asp_traffic_rules.md`, `docs/conventions.md`).
3. Build Python–Clingo bridge: fact builders, one-shot batching, demand gates, `#show` scan, cull radius.
4. Build correction engine(s): heuristic fixpoint first, then ASP-constrained QP + re-validation.
5. Load nuScenes data + real map extraction (lanes, widths, directions, intersections, tiled crossings/walkways, ego-frame transform).
6. Evaluate: L2, collision rate, violation detection, inference time; then tracked-replay and CARLA closed-loop (violation rate/mile, intervention rate, min TTC, replan fidelity).

**Methodology (intended):** SparseDrive proposes → ASP disposes (violations + continuous bounds) → continuous optimizer proposes repair → ASP re-validates; warm temporal inference (N-2) for prediction quality; ablations B0/B1/B2/B3 × A1–A7 on D1 (tracked replay), D2 (frozen dump), D3 (CARLA); threshold/QP sweeps; frozen JSON artifacts as measurement ledger.

**Hypotheses (explicit in eval design):** (H1) warm beats cold; (H2) shield fixes a substantial fraction of unsafe real predictions; (H3) QP beats heuristic on rate and/or latency; (H4) joint-horizon solving beats per-timestep boxes on moving threats; (H5) closed-loop shield reduces collisions/interventions vs unshielded. Measured: H1 supported; H2 partially (0.50 with 5/10 give-ups); H3 rejected on rate, partially supported on pure-lane latency only; H4 unresolved after 3 increments; H5 weakly suggested (n=2) with major caveats.

**Assumptions (load-bearing, often unstated):** 3 s horizon is sufficient (`horizon_s: 3` stamped; blind past 3 s + 1 s label shift documented in `whatodo.md` N-3); constant-velocity agent rollouts at STEP_DT=1.0 s are adequate context; nuScenes-mini 10 scenes generalize; Clingo solve without timeout is acceptable; `on_failure='brake'` (emergency hold) is an acceptable fallback semantic; CARLA lane-plan engine + oracle context + kinematic actors approximate real hazards.

**Claimed contributions (paper + README):** 63-rule integer catalog; checker architecture meeting 50/100 ms budgets on synthetic checks; constraint emission + pure-NumPy PGD corrector with re-validation; measured verdict ledger across four protocols; CARLA pilot as first behavioral evidence. Limitations are fenced in the abstract (horizon-joint gap pointed as future work) — a genuine strength of the reporting culture.

**Direction changes (documented, not hidden):** N-3(b) extrapolation dropped (20 artifact hits); N-3(c) model-head extension killed (retrain needed); N-1 map limits/types honestly omitted (no posted limits in nuScenes data → default cap gated to bare trajs only); multi-shot deferred (dynamics dominate); parked-vs-live answered via series variance instead of box classes; P-13 nav/ego deferred (weak conditioning, mapping unverified); A4/A6/A7 + B3 not run; P-26 Epic window scrapped to backlog (6 GB VRAM binding).

## C. Actual Architecture

```
6× cameras (704×256) + ego2global + timestamp [+ nav_cmd/ego_status]
  → SparseDrivePlanner.predict (cold, reset_temporal every call)
      OR begin_sequence/predict_frame×N/end_sequence (warm, N-2)
  → (6,2) native plan @0.5 s + boxes (N,7) + scores (N,) + velocities (N,3)
  → SafetyLayerPipeline.run:
      resample → checked (4,2) [zeros(1,2); traj[1::2][:3]], T=0 anchor, horizon_s=3
      _detections_to_trajectories: score≥0.5, top-20, CV rollout @STEP_DT
      TrajectoryChecker.check(traj, agents, map, lights, zones)
        → (is_safe, violations) | + constraints dict if include_constraints
      if unsafe → TrajectoryCorrector.correct (heuristic fixpoint)
                 OR CorrectorQP.correct (PGD + re-validate ×3 + flagged fallback)
  → result dict {original_trajectory (6,2 native), safe_trajectory (4,2 checked),
                 violations, is_safe, horizon_s, timing_ms{planner,checker,corrector},
                 corrector_mode}  |  run_batch adds 9-key stable error schema
```

Experiment harnesses **bypass** `pipeline.run()` and wire components directly (reusing only `SafetyLayerPipeline._detections_to_trajectories` as a static helper): `run_calibration.py` (cold/warm + `--corrector` + `--dump-trajs`), `replay_eval.py` (tracked annotations + `--corrector heuristic|qp`, warm default), `run_temporal.py` (warm-vs-cold), `ablate_corrector.py` (GPU-free frozen dump), `sweep_thresholds.py` / `sweep_qp_params.py` (GPU-free sweeps), `carla_bridge.py` + `carla_context.py` + `carla_scenarios.py` + `run_closed_loop.py` + `carla_metrics.py` (closed-loop). Full `SafetyLayerPipeline` instantiation is used only by `tests/test_pipeline.py`, `tests/test_all.py`, `experiments/run_evaluation.py`, `debug_scene7.py` — i.e. the most-cited numbers come from harness-direct wiring, not the shipped `pipeline.run()` path. This is documented, not deceptive, but matters for INTEGRATED assessments.

**Component roles:**
- `neural_planner.py: SparseDrivePlanner` — black-box proposer. Cold `predict()` is safe (resets temporal banks that would otherwise `KeyError` on missing `img_metas`); warm `predict_frame()` is the measured path. Real weights optional; placeholder is seeded deterministic cruise + 2 static boxes.
- `data_loader.py: NuScenesLoader` — sensor/map/GT/agent supplier. Real map extraction is discretized arcline lanes + polygon widths + intersections + tiled crossings/walkways, ego-frame transformed; **deliberately omits** `road_type`/`speed_limit`; lights are `{}` on real data (honest no-knowledge); `estimate_ego_status` returns 18-dim state with only planar velocity observable.
- `checker.py: TrajectoryChecker` — sole safety arbiter. Pre-concatenates catalog via `_build_blob()` following `basic.lp` include order; `_cull_agents` (150 m or closing-fast-enough); one-shot `_FactBatcher`; demand-gated proximity/derived/merge/lane-membership builders; `_shown_atom_to_dict` + `_group_constraints` (ego-only families). Constraints never affect verdict. `get_safe_trajectory()` is a thin delegating wrapper (kept for 2 tests).
- `correction_strategies.py` — pure dispatch data (`SPEED/COLLISION/LANE/STOP/FOLLOW/COMFORT` frozensets, `RULE_GROUPS`, `ADVISORY_RULES={'late_signal'}`, `DEFAULT_PARAMS`); consumed only by corrector (IF-1 single source of truth).
- `corrector.py: TrajectoryCorrector` — heuristic fixpoint: group-by-timestep → `strategy_for(rule)` → `_apply_correction` (tail scale/shift/project/hold/smooth/boost), stagnation break (identical set 3×), dirty-tail snapshot guard, `group_cap=40`, final re-check; `on_failure='raise'|'brake'` (`_hold_position` freeze + `emergency_hold_uncorrectable` entry).
- `constraint_optimizer.py: ConstraintOptimizer` — pure-NumPy projected gradient: index boxes/moving-boxes/ranges/caps/speeds → per-iteration `orig`-attraction + lane spring → inner `joint_iters` (default 5) alternation (clip boxes → moving boxes → ranges → speeds → accel clamp → `_jointly_feasible` vs `feas_tol_cm`) → pin T=0; honest `status: optimal|projection_cycle`.
- `corrector.py: CorrectorQP` — 3 solve/re-validate rounds with `_filter_bounds` (`full|caps|boxes`), `_merge_constraints` union (tightest wins), `_qp_entries` (>1 cm moves), flagged heuristic fallback or raise. `_filter_bounds` routing is what A2/A3-style ablations actually test.
- `evaluation.py: MetricsCalculator` — static L2/collision/violation-detection/FDR/false-positive/avg-time/yaw-aware footprint. Consumed by harnesses + tests; **imported but unused** in `pipeline.py`.
- `utils.py` — vector/kinematics helpers + `trajectory_to_facts`; **no importers found** in `asp-safety` (dead code sign).
- Configs: `correction_strategies.yaml` is actually loaded (keys filtered to `DEFAULT_PARAMS`); `default.yaml` is documentation-only (no loader reads it — stated in P-20 note and confirmed by grep: only `corrector_mode`/`DEFAULT_PARAMS`/yaml-name matches, no `default.yaml` load).

## D. End-to-End Execution Pipeline

1. **Inputs:** `NuScenesLoader.get_scene_sample()` → images `(6,3,256,704)` canonical FRONT/FL/FR/BACK/BL/BR order, resized to 704×256, intrinsics rescaled; extrinsics = cam_T_lidar; ego2global + timestamp from LIDAR_TOP; or placeholder equivalents (seeded, `int_0` red-light scene for reachable-red coverage). `get_scene_frames()` walks `sample['prev']` for warm history. CARLA path substitutes `carla_context.build()` (actors→CV rollouts ×100 cm, lights with 30 m signalized-approach selection + cluster radius + `[0..5]` red span, map via waypoint route-ahead, zones) — with documented axis swap (planner lateral/forward → checker forward/lateral), image vertical flip, and `F=diag(1,-1,1,1)` handedness adaptation verified by P25-A projection sanity (left u=246.7 / right u=457.3 vs cx=352).
2. **Proposal:** planner predicts native `(6,2)` @0.5 s (t=0.5..3.0 s, ego/lidar frame x-forward/y-left). `nav_cmd` defaults `[1,0,0]` (head semantics UNVERIFIED); `ego_status` zeros unless warm-supplied. Fail-loud `_postprocess` (missing `final_planning` or misshapen planning/scores raise; empty detections legal; 10-dim boxes sliced to 7 + velocities).
3. **Context transform:** pipeline resamples to checked `(4,2)` (`zeros(1,2); traj[1::2][:3]`, T=0 anchor from current ego pose, length-asserted, `horizon_s: 3` stamped); detections→agent trajs (score≥0.5 per P-5 sweep knee, cap 20, checker-culled); map→cm ego-frame dict; lights/zones/peds/weather/intent→facts. Calibration and pipeline both enforce this; horizon label shift (pred[1] asserted as T=0) is explicit.
4. **Check:** single Clingo ground+solve over blob; shown atoms parsed to violation dicts `{rule,time,type,...}` (+ optional `constraints` dict / `include_internal` atoms which never affect `is_safe`). Warnings never flip safe. Bare-traj 50 km/h cap (squared 1929321) gated on no-mapped-lanes only.
5. **Correct:** heuristic or QP per `corrector_mode`; both minimize displacement vs original; both re-check; both support brake-fallback give-up semantics (flagged entries, not silent). Corrector latency dominates wall time (seconds, not ms).
6. **Output/consumption:** result dict consumed by tests (shapes, red-light e2e, error schema, mode pin), calibration/replay summaries (L2, GT/pred/fixed safe rates, timing split, horizon stamp), ablation/sweep JSONs, CARLA run JSONs → `carla_metrics.py` aggregates (collision rate, violations/mile, intervention rate, min fidelity, wall/sim times). `run_evaluation.py` is a placeholder batch demo, not a measurement source. Discard points: map vectors/motion forecasts/mode scores ignored; internal atoms discarded unless requested; `MetricsCalculator` not called inside pipeline (offline only).

## G. ASP Rules and Safety Mechanism

**Representation:** integer-cm facts (`pos/4`, `speed2`/`velocity_sq` squared, `lane/4`, `road_type`, `speed_limit` linear + squared at comparison, `light_state`, `intersection`, zones, ped/crosswalk/sidewalk boxes, `fixed_obstacles`, `no_passing_zones`, `merge_lanes`, `conflict_points`, `oncoming_lanes`, `controls_approach`, intent/occupancy/time builders). Helpers in `rules/helpers.lp` (267 lines): `dist2`, `heading`, `on_segment` collinearity + bbox, `in_lane` gated on `use_asp_in_lane`, `#show` block declaring violation/hazard/warning/insufficient + internal arbitration + all `constraint_*` families. `rules/basic.lp` aggregates includes + `total_violations` + `safe(ego)`; `_build_blob` replicates include order (P-12 fix: blob previously dropped basic.lp body so `total_violations` never derived).
